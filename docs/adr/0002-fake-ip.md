# ADR 0002. Доменные правила через fake-IP

Статус: принято (2026-10-29).

## Контекст

Правила маршрутизации — в основном домены (`cursor.com`, `*.google.com`), а маршруты ОС
работают по адресам. Клиент Amnezia резолвит домен один раз при подключении и прописывает
маршруты: CDN с меняющимися адресами и новые поддомены выпадают из туннеля, а каждое
изменение списка требует перестроить таблицу маршрутов. На macOS и Android механизмы
маршрутов разные, а перехватить DNS можно одинаково — интерфейс объявляет свой DNS-сервер.

## Решение

Системный DNS указывает на прокси `10.255.0.1` (`dns::DnsProxy`). Запрос A к домену из правил
получает ответ из диапазона `198.18.0.0/15` (`dns::FakeIpPool`, TTL ответа 60 с, запись живёт
24 ч без обращений); настоящий адрес прокси резолвит через активный движок заранее
(`router::NetResolver::tunnel`) и отдаёт NAT для подстановки при первом пакете. В интерфейс
направляется весь диапазон fake-IP — маршруты ОС не меняются при появлении новых адресов.
AAAA для доменов правил не отдаётся: туннель IPv4-only (правило 9), трафик идёт по A.
Запросы к прочим доменам уходят исходным резолверам системы напрямую (режим по умолчанию
«только домены правил через туннель») или через движок (режим «весь DNS через туннель»).
Исключения (`exclude_domains`, `exclude_ips` наборов и режимов) побеждают включения
(`rules::RuleBook`); выключенный набор → его fake-IP отбрасываются как `NotInRules`.

## Последствия

- Поддомены и CDN попадают в туннель целиком, правила применяются на лету без переподключения.
- Домен виден прокси, а не провайдеру; у админа в журнале домены тоже не пишутся.
- Приложения с собственным DNS (DoH) мимо прокси в туннель не попадают — известное
  ограничение подхода, как и у любого fake-IP-резолвера.
- Kill switch: при мёртвых движках DNS доменов правил отвечает SERVFAIL, пакеты в fake-диапазон
  отбрасываются — защищённое напрямую не уходит (ист. 33).
