# ADR 0011. Автопереключения между хостами нет

Статус: принято (2026-10-29).

## Контекст

У заказчика два хоста: на основном сидит он, на дополнительном — его знакомые. О запасном хосте он сказал: «Нет, такое нельзя, потому что если хост мой основной недоступен, то мне надо сначала определённые приложения защитить, которые не должны бегать по разным IP-адресам. Поэтому автоматическое переключение между хостами создаст мне проблему».

## Решение

Подписка несёт ровно один хост, пользователь привязан к одному хосту. Автовыбор (ADR 0008) переключает только движки внутри хоста, а у всех движков хоста один внешний IP, поэтому смена движка адрес не меняет. Защищённый трафик не уходит ни через другой хост, ни напрямую: когда хост недоступен, сессия показывает «Нет связи с хостом», а трафик по правилам отбрасывается (ADR 0002). На другой хост пользователь переходит вручную: импорт другой личной ссылки заменяет подписку целиком после подтверждения, свои правила сохраняются. Отдельного переключателя хостов в приложении нет.

## Почему

Отвергнуто:

- Запасной хост, на который клиент уходит сам, когда основной недоступен. Приложения, которые защищает заказчик, в этот момент оказались бы на другом адресе — это ровно то, что он запретил.
- Подписка со списком хостов и автоматическим выбором. По сути тот же запасной хост, только внутри подписки: адрес так же меняется без ведома пользователя.

## Последствия

- Недоступный хост — полный перебой для защищённого трафика, пока пользователь сам не перейдёт на другой хост. Это единая точка отказа на каждого пользователя, и заказчик принял её сознательно: сначала защита приложений, потом доступность.
- Все движки одного хоста обязаны выходить с одного IP: серверные части стоят на одной машине. Третий движок на другой машине нарушил бы этот инвариант; приёмка сверяет внешний IP при AWG и при CSQTT.
- Переход на другой хост рвёт текущие соединения (у приложений меняется внешний адрес), поэтому это ручное действие с подтверждением, а не фоновое событие.
- Перенос человека на другой хост — это новая личная ссылка от нужного хоста, а не настройка в клиенте.
- Отсутствие смены хоста проверяется приёмкой: в коде такой операции нет.
