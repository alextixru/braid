# ADR 0009. Одно ядро `Core` на процесс — для Flutter и для службы Android

Статус: принято (2026-10-29).

## Контекст

Заказчик: «Flutter + Rust, один код». На Android VPN держит служба, которую система поднимает и без окна (always-on после перезагрузки), поэтому ядро должно стартовать без движка Flutter.

## Решение

- Вся логика — роутер, автовыбор, подписка, журнал — живёт в Rust-ядре за единственным фасадом `Core`.
- Flutter — оболочка: показывает состояние и шлёт команды через мост `braid_ffi`; сетевой логики в нём нет, дескриптор интерфейса через Dart не проходит.
- Ядро создаётся один раз на процесс. На macOS его строит мост приложения; на Android — служба через JNI, а мост берёт уже созданное ядро, так что окно и служба работают с одним экземпляром в одном процессе.
- JNI-входы, которым нужно ядро, живут в `braid-runtime`, а не в `braid-platform`: ядро зависит от платформы, и платформа не может вызывать ядро обратно.

## Почему

Отвергнуто:

- Ядро в изоляте Flutter, а дескриптор интерфейса передаёт Dart (так сделан Astral: служба → EventChannel → Dart → ядро). VPN оказывается привязан к живому изоляту и процессу окна, а система стартует службу и без окна.
- Служба в отдельном процессе с Binder или Messenger (так сделан Amnezia). Рядом с мостом появляется второй канал для состояния и команд, а схема расходится с macOS, где ядро живёт в процессе приложения.
- JNI-входы в `braid-platform`. Ядро зависит от платформы (трейт `Platform` и тестовая платформа в памяти), и вызов ядра отсюда замкнул бы зависимость в цикл.
- Отдельные нативные приложения на каждую ОС. Заказчик хочет «один код», а Windows и Linux заложены на следующий заход: Flutter уже собирает macOS, Linux и Windows в форке FOCSQ, и Android добавляется как ещё одна платформа.

## Последствия

- Поведение проверяется на Rust без окна и без привилегий; Flutter тестируется на подменённом мосте.
- На Android ядро существует, только пока есть процесс. Пока служба его не создала, мост отвечает «Сервис запускается», а окно не зовёт `connect` одновременно со стартом службы — иначе гонка с привязкой платформы.
- Граница JNI разнесена по двум крейтам: платформенные входы лежат в `braid-platform`, входы к ядру — в `braid-runtime`, `JNI_OnLoad` один на библиотеку. Это правило надо знать, чтобы найти нужный вход.
- Связка `flutter_rust_bridge` + cargokit взята из FOCSQ, но там Android не было: на этой платформе она в проекте новая, и собирается она только в CI.
