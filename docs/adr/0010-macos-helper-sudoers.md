# ADR 0010. macOS: root-помощник по правилу sudoers, без LaunchDaemon

Статус: принято (2026-10-29).

## Контекст

Заказчик: «Root-помощник utun, как в FOCSQ». Интерфейс utun создаёт только root, Network Extension недоступен без Apple Developer, а приложение ставится zip-архивом с ad-hoc-подписью.

## Решение

Привилегированная часть — отдельная программа `braid-helper`, наследница помощника FOCSQ. Она создаёт интерфейс, ставит адрес, MTU, маршруты и DNS, отдаёт дескриптор приложению через SCM_RIGHTS, правит маршруты на лету и откатывает всё по команде `down` или при обрыве связи. Помощник запускается один раз на сессию приложения; постоянного root-демона нет.

Запускает его `sudo -n` по правилу в `/etc/sudoers.d/braid`. Правило при первом подключении ставит само приложение через `osascript` с паролем администратора и с согласия пользователя; пока правила нет, помощник стартует через `osascript` с запросом пароля. Правило пишется не на бинарник внутри `.app`, а на его копию в каталоге root (`/Library/PrivilegedHelperTools/braid-helper`, root:wheel), сверенную по SHA-256 и названную в правиле с `sha256:` — иначе владелец `.app` подменил бы файл, которому sudo доверяет без пароля; после обновления приложения копия отстаёт, и приложение предлагает переустановить правило. Собеседника помощник проверяет по `LOCAL_PEERCRED` (uid приложения), а хвосты прошлой сессии — интерфейс, маршруты, DNS — убирает при старте.

## Почему

Отвергнуто:

- LaunchDaemon, как у Amnezia. Её установщик отдаёт бандл root'у и закрывает на запись, иначе пользователь подменит бинарник root-службы; у нас же бандл из zip принадлежит пользователю. Кроме того, такой демон живёт между сессиями, а его сокет у Amnezia открыт любому локальному пользователю — это мы не повторяем.
- Пароль на каждом подключении (так работает FOCSQ). Остаётся только запасным путём, пока правила нет.
- `SMAppService` и `SMJobBless`. Работа с ad-hoc-подписью не подтверждена, строить на непроверенном не стали.
- Network Extension: нужна программа Apple Developer (ADR 0006).

## Последствия

- Пароль администратора нужен один раз — при установке правила, дальше диалогов нет.
- Правило привязано к хешу, поэтому после каждого обновления приложения его ставят заново и снова вводят пароль. Зато подмена бинарника внутри пользовательского бандла root не даёт.
- Правило лежит вне бандла, и простое удаление приложения его не убирает: оно остаётся в системе, пока его не уберут отдельно.
- Помощник доверяет по uid: любой процесс того же пользователя, дотянувшийся до сокета, может слать ему команды. Набор команд узкий — интерфейс, маршруты, исключения, уборка, отбой.
- После `kill -9` помощника DNS и маршруты остаются перехваченными до следующей уборки при запуске приложения (в FOCSQ именно так и было).
- Сам помощник проверяется на подставной системе (`--dry-run`), а встраивание в бандл без Xcode локально не проверить: `.app` собирает только CI (ADR 0006).
