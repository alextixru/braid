# ADR 0001. Один tun-интерфейс и симметричный NAT на каждый поток

Статус: принято (2026-10-29).

## Контекст

Два движка (AmneziaWG, CSQTT) и слот под третий работают одновременно: активный несёт
трафик, запасной держится подключённым заранее. Каждый протокол даёт клиенту свой адрес в
туннеле (AWG — `client_ip` из конфига, CSQTT — из `TUNCONF`), а у одного интерфейса ОС —
один адрес. Три приложения с тремя интерфейсами (как у исходных клиентов) конфликтуют за
маршруты и DNS и не дают переключаться без разрыва.

## Решение

Интерфейс один и принадлежит Braid; движки интерфейсов, маршрутов и DNS не трогают
(`Engine::send` принимает готовый IP-пакет, ответы приходят колбэком `EngineIo::inbound`).
Адрес интерфейса фиксированный — `10.255.0.2`, собеседник и DNS-прокси — `10.255.0.1`
(`braid_core::router`). Роутер делает полный NAT для каждого потока (5-tuple):
`nat::FlowTable::outbound` подменяет источник на адрес движка, назначение — на настоящий
адрес (для fake-IP), `inbound` восстанавливает; контрольные суммы IPv4/TCP/UDP/ICMP
пересчитываются инкрементально (`nat::checksum`). Поток закрепляется за движком на всё время
жизни; новые потоки идут в активный. При смерти движка его TCP-потокам отправляется RST
(`Router::drop_engine`), чтобы приложения переподключились сразу через новый движок.

## Последствия

- Переключение движка не меняет интерфейс, маршруты и DNS — без разрыва для остального трафика.
- Живой перенос соединения невозможен (у каждого протокола свой NAT на сервере) — потоки
  мёртвого движка обрываются, но RST сокращает заминку с минут до секунд.
- MTU интерфейса — минимум по движкам (CSQTT фиксирует 1300).
- Симметричный NAT для всех движков проще особого случая для одного; проверяется тестами на
  `MemoryPlatform` без привилегий (`core/braid-core/tests/router_*.rs`).
